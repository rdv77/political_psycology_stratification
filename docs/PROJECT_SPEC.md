# PROJECT_SPEC — Семантическое пространство (Шмелёв)

Этот документ — живое описание алгоритма, фич и конфигурации. Обновляется синхронно с изменениями в коде.

## Цель
Построить воспроизводимый пайплайн для формирования семантического пространства политических партий по теории семантических конструктов (Шмелёв):
- сбор объектов пространства (страны → партии),
- извлечение признаков (характеристик),
- дедупликация признаков в интегральный список,
- оценивание объектов по интегральной шкале (0–10),
- факторный анализ и интерпретация факторов,
- кластеризация, t‑SNE и отчёты.

## Архитектура
- `config/config.yaml` — конфиг (провайдеры, лимиты/бюджеты, логирование, фичефлаги, анализ, пути, промпты).
- `prompts/` — шаблоны промптов: объекты, партии, признаки, дедуп, оценивание, описания факторов и кластеров.
- `src/` — код клиентов (Perplexity/OpenAI), утилиты (логирование, параллелизм, кэш, стоимость), схемы данных и этапы пайплайна.
- `data/` — сырые/промежуточные/готовые артефакты.
- `reports/`, `plots/`, `logs/` — отчёты, графики и логи соответственно.
- `cli.py` — запуск стадий и режимов.

## Конфигурация (ключевые секции)
- `providers.perplexity` — ключ и модель Perplexity (встроенный веб‑доступ).
- `providers.openai` — ключ и модели OpenAI для оценок/дедуп/описаний.
  - `model_search` — модель для шагов с веб‑поиском (например, `gpt-5-search-api` или `o4-mini-deep-research`).
- `limits` — жёсткие лимиты: max_countries, max_parties_per_country, max_traits, max_tokens_per_call, max_cost_usd, max_concurrent_requests.
- `features` — фичефлаги для включения/отключения этапов (модульность).
- `logging` — режимы dev/prod/quiet, уровни и вывод в консоль/файл, формат (text/json), ротация, метрики LLM.
- `governance` — требование подтверждения пользователя для выполнения (флаг `--apply`).
- `analysis` — настройки ФА (порог дисперсии последнего фактора, ротация, max_factors), кластеризации (метод, выбор k), t‑SNE.
- `scoring.max_traits_per_call` — максимальное число характеристик в одном LLM‑вызове при оценивании (по умолчанию 10). Список признаков делится на чанки этого размера; результаты объединяются по партии.
- `dedupe.similarity_threshold` — порог схожести (0..1) для объединения похожих признаков после LLM‑дедупликации. По умолчанию 0.7. Увеличивайте порог (например, 0.85–0.9), чтобы оставлять больше близких формулировок и объединять только почти идентичные.
- `collect.provider` / `collect.fallback_provider` — провайдер для шагов 1–2: `perplexity` или `openai_search` с фейловером.
- `io`, `locale`, `user_input`, `prompts`, `resilience`, `ethics` — директории, язык канонизации, пользовательские объекты, пути промптов, устойчивость, политика сохранения сырых ответов.

## Алгоритм по шагам (1–13)
1. Список стран (Perplexity или OpenAI Search), отсечение по лимиту, объединение с ручным вводом.
2. По каждой стране — сбор партий (Perplexity или OpenAI Search) с описанием, лидерами и идеологиями.
3. Инъекция пользовательских объектов (если включено).
4. Для каждой партии — 5–15 характеристик (OpenAI), нормализация языка.
5. Дедуп/канонизация списка признаков (OpenAI), отсечение до лимита.
6. Батч‑оценивание каждой партии по интегральному списку (OpenAI, 0–10, JSON).
7. До запуска — обязательная смета запросов/токенов/стоимости и гейт бюджета.
8. Факторный анализ: подбор числа факторов до порога дисперсии последнего фактора, ротация.
9. Описание факторов (OpenAI) по топ положительным и отрицательным нагрузкам.
10. Группы партий с наибольшими весами по факторам (Perplexity) — что их объединяет.
11. Кластеризация факторных нагрузок, выбор k (силуэт), расстояния до центроидов.
12. t‑SNE до 2D, визуализация всех партий с окраской по кластерам; партии из инъекций выделяются отдельным цветом и формой, для них добавляются подписи; дополнительно строятся 2‑D scatter‑графики по парам факторов.
13. Тематические описания кластеров (Perplexity) с акцентом на пользовательские партии и «не вошедшие» кластеры.

## Логирование
- dev: максимально подробные логи в консоль (DEBUG), метрики LLM (токены, стоимость, кэш‑хиты), ретраи, тайминги.
- prod: тихий режим (минимум в консоль или OFF), запись в файл, уровень CRITICAL, ротация логов.
- quiet: только файл и только CRITICAL.

## Бюджет и безопасность
- «Сухой прогон» (`--dry-run`) оценивает число запросов, токены и стоимость.
- Запуск шагов только после подтверждения (`--apply`) при включенном `governance.require_user_approval`.
- Превышение `limits.max_cost_usd` или `limits.max_tokens_per_call` — блокировка запуска.

## Данные и форматы
- `countries.json`, `parties.jsonl`, `traits.json` — списки стран, партий и признаков.
- `scores.parquet` — матрица оценок (|parties|×|traits|) в [0,10].
- `factors.parquet`, `clusters.parquet`, `tsne.parquet` — нагрузки/счёта, кластера и 2D‑координаты.
- `reports/*.md`, `plots/tsne.png` — отчёты и визуализации.

## Режимы запуска
- План/оценка: `python -m src.cli run --stage all --dry-run`.
- Выполнение: `python -m src.cli run --stage all --apply`.
- Тишина: `--quiet` или `logging.mode=prod`.

### Быстрая оценка бюджета
- Команда: `python -m src.cli run --stage budget`
- Вывод: помодульный разбор (кол-во вызовов, оценка токенов in/out и их totals по шагу, модель/провайдер, стоимость по шагам) и общий итог по стоимости и токенам. Источники оценок:
  - Фактические размеры датасета, если уже есть артефакты (`countries.json`, `parties.jsonl`, `traits.json`, `factors_meta.json`).
  - Иначе — лимиты из `limits.*` и допущения по токенам.
- Допущения по токенам можно переопределить в `config.yaml` секцией `budget.assumptions` (опционально). На скоринге учтено чанкирование: число вызовов = `parties_count * ceil(traits_count / scoring.max_traits_per_call)`, токены per call масштабируются по размеру чанка:
```yaml
budget:
  assumptions:
    objects: { in: 500, out: 600 }
    parties: { in: 1200, out: 2000 }
    traits_extract: { in: 900, out: 400 }
    traits_dedupe: { in: 2000, out: 600 }
    factor_describe: { in: 400, out: 350 }
    factor_groups_report: { in: 1200, out: 1200 }
    cluster_thematic_report: { in: 3000, out: 2000 }
    estimate_n_factors: 6
```

## Секреты и переменные окружения
- Храните ключи API в локальном файле `.env` (не коммитить). Пример: `example.env` — переименуйте в `.env` и заполните `PPLX_API_KEY` и `OPENAI_API_KEY`.
- CLI автоматически загружает `.env` (через `python-dotenv`) до чтения `config.yaml`.
- В `config/config.yaml` значения ключей указываются как `${PPLX_API_KEY}` и `${OPENAI_API_KEY}` — берутся из окружения.

## Кэширование и экономия
- Perplexity Structured Outputs: на шагах 1–2 используется `response_format.type=json_schema` (см. [Structured Outputs Guide](https://docs.perplexity.ai/guides/structured-outputs)) для гарантированного JSON. Первый запрос со схемой может иметь задержку (прогрев).
- Клиентские кэши LLM: ответы Perplexity/OpenAI кешируются на диске по ключу `(messages, model, параметры)`; повторные запросы с тем же промптом читаются из кэша.
- Очистка кэша (старт заново): удалите содержимое директории из `io.cache_dir` (по умолчанию `cache`). Пример PowerShell: `Remove-Item -Recurse -Force cache\*`. Для полного пересчёта этапов также удалите файлы в `data/`, `plots/`, `reports/`.
- Артефакты: промежуточные файлы (`countries.json`, `parties.jsonl`, `traits.json`, `scores.parquet` и т.д.) позволяют пропускать этапы при повторных запусках.
- Стабильные промпты: детерминированная сериализация списков/JSON повышает шанс кэш‑хита.
- Cached input (OpenAI): общий пролог (инструкции + часть неизменного контента) может тарифицироваться по сниженной ставке cached‑input; возможно к включению позже.

## Изменения (changelog)
- Добавлена стадия `budget`: оценивает количество вызовов, токены (per‑call и totals) и стоимость по шагам, выводит общий итог. Стоимость считает:
  - OpenAI — по ценам per 1M tokens (как в оф. документации).
  - Perplexity — по ценам per 1M tokens.
- Скоринг по признакам теперь чанкируется: `scoring.max_traits_per_call` (по умолчанию 10). Для каждой партии список признаков разбивается на чанки, каждый чанк оценивается отдельным запросом, результаты объединяются; валидация и ограничение [0..10] включены.
- В расчёте бюджета учтено чанкирование скоринга (calls = `parties * ceil(traits / max_traits_per_call)`).
- Добавлена поддержка `.env` (через `python-dotenv`), `.env` игнорируется в VCS; ключи подставляются в `config.yaml` через `${VAR}`.

## CLI команды и этапы
- Общий вид: `python -m src.cli run --stage <stage> [--apply] [--sample] [--quiet]`
- Доступные стадии:
  - `collect` — сбор стран и партий (с учётом `features.collect_*`).
  - `traits` — извлечение характеристик для партий.
  - `dedupe` — дедупликация/канонизация признаков.
  - `score` — оценивание партий по признакам (чанки по `scoring.max_traits_per_call`, параллелизм по `limits.max_concurrent_requests`).
  - `fa` — факторный анализ.
  - `describe` — LLM‑описания факторов с долями дисперсии.
  - `cluster` — кластеризация факторных баллов.
  - `tsne` — t‑SNE визуализация всех партий; инъекции выделяются и подписываются.
  - `report` — отчёт по кластерам (размер/%, ближайшие к центроиду, описание с веб‑ссылками).
  - `budget` — оценка бюджета без выполнения шагов.
  - `all` — последовательный запуск всех включённых фич.

- Полезные флаги:
  - `--apply` — требуется для выполнения шагов при включённом `governance.require_user_approval`.
  - `--sample` — уменьшает лимиты (страны/партии/признаки) для быстрого прогонов.
  - `--quiet` — минимизировать логи в консоль (см. также `logging.mode`).

## Возобновление работы (resume) и типичные сценарии восстановления
- Повторный запуск с нужной стадии: пайплайн идемпотентен по артефактам. Если предыдущие артефакты существуют, следующий шаг их использует.
  - Пример продолжения с места сбоя после описаний факторов:
    - `python -m src.cli run --stage describe --apply`
    - `python -m src.cli run --stage cluster --apply`
    - `python -m src.cli run --stage tsne --apply`
    - `python -m src.cli run --stage report --apply`

- Блокировки файлов (Windows): `PermissionError: reports\\factors.md`
  - Закройте файл в редакторе/просмотрщике и повторите соответствующую стадию.
  - При необходимости удалите файл: `Remove-Item reports\factors.md -Force` (PowerShell).

- Отсутствует Parquet‑движок:
  - Сообщение: `ImportError: Unable to find a usable engine; pyarrow/fastparquet`.
  - Решение: `pip install pyarrow` (включено в `requirements.txt`). На скоринге предусмотрен аварийный CSV‑фоллбэк, но дальнейшие шаги ожидают Parquet — установите `pyarrow`.

- NaN в факторном анализе: `ValueError: Input contains NaN`
  - Реализована автоматическая очистка: удаление all‑NaN и нулевой дисперсии, заполнение средними, удаление неполных строк, ограничение числа факторов числом доступных признаков.
  - Достаточно повторно запустить стадию `fa`.

- t‑SNE: `perplexity must be < n_samples`
  - Перплексити автоматически зажимается до валидного значения `< n_samples` (и ≤ 50) с логированием корректировки.
  - Повторный запуск `tsne`.

- Медленный скоринг
  - Включён параллелизм по партиям с ограничением `limits.max_concurrent_requests` (по умолчанию 8). Увеличивайте осторожно с учётом лимитов API.
  - Чанк‑оценивание по признакам: `scoring.max_traits_per_call`.

- Смена провайдера/модели поиска (сбор стран/партий)
  - `collect.provider`: `openai_search` (модель `providers.openai.model_search`) или `perplexity`; при ошибках включится фоллбэк `collect.fallback_provider`.

### Настройка дедупликации признаков
- Управляется параметром `dedupe.similarity_threshold` в `config/config.yaml` (по умолчанию `0.7`).
- Чем ВЫШЕ порог (например, `0.85–0.9`), тем МЕНЬШЕ признаков будет объединяться (остаются близкие формулировки). Чем НИЖЕ, тем агрессивнее схлопывание.

Пример:

```yaml
dedupe:
  similarity_threshold: 0.85
```

После изменения порога выполните пересчёт этапов:

```powershell
python -m src.cli run --stage dedupe --apply
python -m src.cli run --stage score --apply
python -m src.cli run --stage fa --apply
python -m src.cli run --stage describe --apply
python -m src.cli run --stage cluster --apply
python -m src.cli run --stage tsne --apply
python -m src.cli run --stage report --apply
```

### Очистка кэша и старт заново
- Только кэш LLM (быстрый перезапуск с теми же данными):

```powershell
Remove-Item -Recurse -Force cache\*
```

- Полный пересчёт артефактов «с нуля» (очистка кэша и результатов):

```powershell
Remove-Item -Recurse -Force cache\* , data\* , plots\* , reports\*
python -m src.cli run --stage all --apply
```

## Визуализации
- t‑SNE (`plots/tsne.png`):
  - Все партии отображаются и окрашены по `cluster_id`.
  - Партии из инъекций выделены красной звёздой с обводкой и подписью названия.

- Факторные 2‑D scatter‑графики (`plots/factors_Fi_Fj.png`):
  - Строятся для пар факторов (1–2), (2–3), …, (8–9) при наличии соответствующих факторов.
  - Точки окрашены по странам, российские партии из инъекции выделены ромбом и отдельным цветом.

## Отчёты
- Факторы (`reports/factors.md`):
  - Для каждого фактора выводится доля дисперсии, топ‑признаки по положительным и отрицательным нагрузкам, затем текст интерпретации (LLM).

- Кластеры (`reports/clusters.md`):
  - Для каждого кластера — размер (в абсолютных значениях и %), список партий, ближайших к центроиду (по расстоянию), и описание кластера (LLM с веб‑ссылками).

## Детали анализа
- Факторный анализ:
  - Подбор числа факторов: увеличиваем от 1 до `analysis.factor.max_factors`, выбирая первое `n`, при котором доля дисперсии последнего фактора < `analysis.factor.min_last_factor_variance` (по умолчанию 3%).
  - Перед ФА выполняется очистка данных: удаление all‑NaN и нулевой дисперсии; заполнение NaN средними значениями столбцов; удаление оставшихся неполных строк; ограничение `max_factors` числом доступных признаков.

- Кластеры:
  - При `analysis.cluster.k_selection = silhouette` значение `k` выбирается по максимуму силуэта в диапазоне `k_range`. При `fixed` используется заданный `k`.
