# Локальный MVP семантических пространств

Дата реализации: 15 октября 2026 года. Первый предметный пример — публичный
политический образ 70 российских политиков в период 15.10.2016–15.10.2026.
Подготовленная выборка и готовый аналитический результат — разные этапы:
состояние этого исследования видно в интерфейсе, анализ начинается после
утверждения объектов и шкал.

## Запуск на этом компьютере

Откройте `Start-SemanticSpace.ps1` через PowerShell:

```powershell
powershell -ExecutionPolicy Bypass -File .\Start-SemanticSpace.ps1
```

Сервис открывается на http://127.0.0.1:8766. Он слушает только loopback,
не публикуется в интернете. Для остановки используйте `Stop-SemanticSpace.ps1`.
Повторный запуск использует работающий сервер. Состояние хранится в `studies/`.
Серверные логи и PID — в игнорируемой папке `.service_runtime/`.

На текущем компьютере запуск использует существующий Python 3.10 из исходного
проекта. На другом компьютере подготовьте `.venv` и установите
`requirements-service.txt`, затем задайте `SEMANTIC_PYTHON` при необходимости.
PDF/DOCX используют bundled Python; слайды — bundled Node и `@oai/artifact-tool`.
Эти пути автоматически находятся в установленном Codex runtime или задаются
`SEMANTIC_EXPORT_PYTHON`, `SEMANTIC_NODE`, `SEMANTIC_NODE_MODULES`.
Репозиторий не включает сам управляемый runtime.

Ключи хранятся только в локальном `.env`: `OPENAI_API_KEY` и `PPLX_API_KEY`.
Клиентский интерфейс получает лишь факт наличия подключения. Ключи не входят
в Git, в HTML или в ответы API. По умолчанию используются заданные в проекте
`gpt-4.1` и `sonar-pro`; параметры переопределяются `SEMANTIC_MODEL` и
`SEMANTIC_SEARCH_MODEL`.

## Последовательность работы

1. Задать область, аспект, период и запрос отбора либо вставить готовый список.
2. Проверить список найденных объектов, исправить состав и утвердить его.
3. Собрать досье и предложенный словарь шкал; проверить определения и полюса,
   поправить словарь и утвердить его.
4. Запустить оценивание и анализ. По умолчанию q и k предлагаются алгоритмом;
   дополнительные настройки позволяют сравнить решения с другими q/k.
5. Просмотреть интерпретацию и скачать отчёт с диаграммами и слайды.

Изменение объекта или определения шкалы отменяет соответствующее подтверждение
и сбрасывает зависимые результаты. Старые импортированные оценки нельзя
повторно анализировать под изменёнными определениями без нового импорта.
Подтверждения в интерфейсе записываются с датой и fingerprint утверждённых данных.
Повторный анализ проверяет основание и контрольную сумму сохранённой матрицы:
если область, период, объекты и шкалы не изменились, оценки используются повторно.
Это сохраняет уточнённые исследователем ячейки при сравнении q/k. Явное новое
оценивание доступно через API с `force_rerate: true`; импорт проверяется отдельно.

## Что находится внутри

- HTTP: Python `ThreadingHTTPServer`, без облака и внешней базы данных.
- Интерфейс: `frontend/`, чистые HTML/CSS/JS, без CDN и сборки.
- Состояние и подтверждения: `src/semantic_service/store.py`.
- Поиск/досье, шкалы, поэлементные оценки и интерпретации: `providers.py`.
- Матрица, Gaussian FA, сравнение размерностей, k-means, устойчивость и карты:
  `analysis.py`.
- Единая модель содержания для MD/HTML/PDF/DOCX/презентации: `reports.py`.
- Экспорт PDF/DOCX: отдельный bundled Python process `export_documents.py`.
- Экспорт PowerPoint: Artifact Tool и finalizer в `presentation.mjs`.

Для каждого объекта сохраняется досье с фактами и ссылками. Признаки
нормализуются по материалам досье; алиасы и число объектов происхождения
сохраняются, но не создают скрытых повторных весов в матрице.
После исходного предложения выполняется отдельная модельная проверка словаря:
переносимость на все объекты, единый аспект, близкие синонимы, явные полюса
без подмены молчания противоположной позицией. Оба предложения и решения
сохраняются; нормализованный словарь остаётся неутверждённым до решения пользователя.
Подтверждённые retrieval citations используются для проверки URL фактов:
список источников, самостоятельно написанный LLM, не авторизует собственные ссылки.
Проверка URL не равна проверке entailment: смысловую поддержку каждой оценки
всё равно нужно проверять исследователю.

Шкалы: два числа 0..5, difference=positive−negative, mass=positive+negative.
Unknown сохраняется отдельно. Все ячейки ссылаются на факты досье; технические
сбои не превращаются в нулевую выраженность. Оценки LLM являются разведочными.
Если после первой оценки не менее 20% шкал объекта остаются неизвестными,
выполняется один целевой добор источников и повторная оценка только неизвестных
ячеек. Наблюдаемые оценки первого прохода сохраняются. Повторный запуск
использует кэш исходных оценок и дополнений к досье, привязанный к версиям данных.

FA моделирует общий сигнал и диагональный шум и вычисляет posterior coordinates
через систему q×q. Сравниваются несколько q и диагностическая PCA parallel analysis;
PCA не называется факторным анализом. Нагрузки и баллы согласованно поворачиваются.
Доли дисперсии — суммы квадратов нагрузок, нормированные на общую дисперсию
стандартизованных шкал. Правила выбора q/k, исключения и неопределённость записаны
в `output/metadata.json`.

До расчёта в каждой итерации сначала исключаются шкалы с менее чем
`max(8, ceil(0.60*n))` известными оценками либо стандартным отклонением не выше
`1e-10`. Затем по оставшимся шкалам исключаются объекты с менее чем
`max(4, ceil(0.60*p))` известными оценками. Итерации идут до стабильного состава;
в результате нужны минимум 12 объектов, 6 шкал и 75% известных ячеек.
Порядок и исключения записаны в diagnostics. Отсутствие достаточных данных
по шкале не означает отсутствия соответствующей идеи в изучаемом пространстве.

K-means использует несколько инициализаций; k сравнивается по разделению,
размерам и устойчивости на 80% подвыборках. Численное предложение не считается
окончательным содержательным доказательством типов. Группы объясняются по
агрегированным отличиям от всей выборки и полным факторным профилям.
В режиме LLM отдельно сравниваются содержательные профили **всех** вариантов k.
Из подходящих по размеру и устойчивости вариантов выбирается содержательно
различимая рабочая типология; допустим вывод, что пространство непрерывно.
Назначенное пользователем k сохраняется, даже если модель рекомендует другое.

### Открытие в Google Docs

Для текста и таблиц скачайте `report.md`, затем в Google Docs выберите
**Файл → Открыть → Загрузить** и укажите файл. Такой импорт описан в
[официальной справке Google](https://support.google.com/docs/answer/12014036?hl=ru).
Открытие загруженного MD непосредственно с Диска также может работать как
редактирование исходного Markdown с сохранением расширения MD; это отдельный
режим, описанный в [справке о файлах разметки](https://support.google.com/docs/answer/18289341?hl=ru).

Для отчёта со встроенными диаграммами скачайте `report.docx`, загрузите его на
Google Диск и откройте в Google Docs. Само открытие Office-файла сохраняет
формат DOCX; преобразование создаёт отдельную копию Google Docs.
Эти режимы различаются в [справке по файлам Microsoft Office](https://support.google.com/docs/answer/9406611?hl=ru).
После импорта проверьте переносы таблиц и диаграмм: другой редактор может
изменить разбивку страниц.

Относительная ссылка `assets/…png` в Markdown не содержит самого изображения
и не даёт Google Docs доступа к локальному диску. ZIP сохраняет структуру
`report.md` вместе с `assets/` для совместимого локального редактора. Для переноса
диаграмм одним файлом используйте DOCX. Создание нативного Google Doc через
аккаунт пользователя в MVP не выполняется: сервис выдаёт файлы для импорта.

Карты объектов и нагрузок признаков показываются отдельно. t-SNE проецирует
полные факторные профили в 2D и не получает названий факторных осей. Кластеры
не рассчитываются по t-SNE. Интересующий объект выделяется и получает отдельный
раздел, не влияя своим статусом на fit или выбор q/k.

## Технический пример на прежних партиях

Исследование `demo-legacy-parties` с названием «Пример: ранее собранные партии»
показывает завершённый процесс анализа и экспорта без новых запросов к моделям.
Оно использует 95 партий и первые 40 признаков прежней сохранённой матрицы.
Это не результат исследования 70 российских политиков и не проверка качества
сокращённого словаря. Пример явно отмечен в интерфейсе и отчёте.

Прежние оценки 0–10 перенесены по формуле `value = x − 5`. Независимые оценки
двух полюсов и их сумма из этих данных не восстанавливаются; ноль означает
прежнюю оценку 5, а не доказанную невыраженность обоих свойств. Исторический
период старой матрицы не зафиксирован; служебная дата импорта не подменяет его.
Подтверждения этого примера помечены как импортированные служебные записи,
пользовательские утверждения нового исследования они не заменяют.

Пример создаётся офлайн командой `python -m scripts.create_mvp_demo`.
Повторный запуск сохраняет существующий пример; `--rebuild` заменяет только
этот явно помеченный пример. Скрипт создаёт MD/HTML и данные для экспорта,
но сам не запускает PDF/DOCX/PowerPoint-экспорт. Остальные исследования
не затрагиваются.

## Бюджет и продолжение

Лимит одного исследования по умолчанию — $20 по заданным оценочным ставкам.
Учитываются токены и резервируются ответы параллельных запросов. Это локальная
оценка, не банковский счёт провайдера. Запросы кэшируются по содержанию, модели
и параметрам; неизменные этапы могут быть продолжены без повторного измерения.
Кэш и ключи исключены из Git. Синтетические панели агентов не включены в MVP.

## Выполненный пилот

Объекты и 26 шкал утверждены пользователем. Оценены все 70 политиков;
1260/1820 ячеек известны. В итоговый расчёт вошли 63 объекта и 17 шкал,
полнота используемой матрицы — 86,3%. Две оси описывают 47,1% дисперсии;
три группы содержат 40, 15 и 8 объектов. Семь профилей исключены по заранее
заданному порогу покрытия, их исходные оценки сохранены.

[Результаты и файлы](../research/russian_politicians_2016_2026/README.md),
[протокол и ограничения](../research/russian_politicians_2016_2026/PROTOCOL.md).
Для этого пилота после основного процесса выполнен последний ограниченный
аудит 13 неполных профилей: добавлено 38 оценок с новым основанием.
Это отдельная исследовательская процедура, не бесконечный автоматический добор.

`python -m scripts.complete_pilot_coverage` показывает план без запросов;
`--apply` разрешает единственный ограниченный добор по зафиксированной основе.
`python -m scripts.finalize_pilot` проверяет готовность; `--apply` пересчитывает
пилот по сохранённым оценкам, заново формирует интерпретацию и экспорт.
Эти команды проверяют подтверждения и привязку исходных оценок к версиям данных.
Повторная генерация словесной интерпретации требует новой редакторской проверки.

Сравнение размерностей пилота выполняется без нового оценивания и API-запросов:

```powershell
python -m scripts.compare_factor_models studies/russian-politicians-2016-2026/study.json studies/russian-politicians-2016-2026/ratings.json studies/russian-politicians-2016-2026/output --selected-k 3:4 --selected-k 4:4
python -m scripts.finalize_factor_comparison
python -m scripts.finalize_factor_comparison --apply
```

Первый шаг сохраняет исходный q2, фиксирует входные данные и создаёт численные
q3/q4 с контрольным k3 и выбранными k4 в `output/models`. Повтор использует
зафиксированные измерительные входы и отклоняет изменённые объекты, шкалы или
оценки. Второй шаг проверяет готовность. `--apply` соединяет расчёты с проверенным
`FACTOR_COMPARISON_INTERPRETATION.json`, обновляет Markdown/HTML/PDF/DOCX/PPTX/ZIP.
Базовый q2 остаётся в основном разделе; сравнение и рекомендация q3/k4 показаны
отдельно. Повтор обычного `finalize_pilot --apply` формирует одиночную модель,
поэтому для сравнительного отчёта нужен именно `finalize_factor_comparison`.

Для презентации пилота сохранён отдельный читательский профиль: только q4/k4,
интерпретации осей и групп, все шкалы и диаграммы с большим числом фамилий.
Сравнительный отчёт при этом остаётся полным. Подготовка и повторный экспорт:

```powershell
python -m scripts.build_q4_presentation_charts
python -m scripts.export_q4_presentation
python -m scripts.export_q4_presentation --apply
```

Первая команда строит пять диаграмм по сохранённой q4-модели без нового анализа
или оценивания. Вторая проверяет готовность. `--apply` экспортирует презентацию,
обновляет ZIP и сохраняет выбор в `study.presentation_config`. MD/HTML/PDF/DOCX
и оценки остаются побайтово прежними. Профиль использует проверенные тексты из
`PRESENTATION_Q4_CONTENT.json`; контрольные суммы защищают от использования
диаграмм другой версии объектов, шкал или модели. При изменении модели сначала
нужно обновить диаграммы. Последующие экспорты учитывают сохранённый профиль.

## Ограничения проверки

Итоговая версия прошла 101 автоматический тест. PDF пилота: 107 страниц,
презентация: 22 слайда; весь рендер проверен, последующие изменения проверены
сравнением изображений и просмотром изменённых страниц. Числа, составы групп,
нагрузки и текстовые выводы сверены между форматами. Контрольные суммы и
границы проверки записаны в [VALIDATION.json](../research/russian_politicians_2016_2026/VALIDATION.json).

Численные, state-machine и HTTP-тесты выполняются автоматически. Артефакты
проверяются отдельно по структуре и рендеру. При недоступном браузере CUA нельзя
утверждать, что проведено визуальное браузерное тестирование интерфейса.
На текущем компьютере браузер CUA недоступен: такой проверки интерфейса нет.
Обновлённый PDF технического примера отрендерен постранично и проверен отдельно
от интерфейса; проверены кириллица, таблицы, заголовки, диаграммы и полнота состава.
HTML и Markdown проверены по структуре, содержанию и доступности файлов диаграмм,
их браузерный просмотр этой проверкой не подменяется.

Экспорт DOCX проходит очистку заголовка от остаточных подчёркиваний и границ,
сохраняет таблицы и встроенные изображения. Постраничный рендер DOCX здесь
недоступен: `render_docx.py` сообщил об отсутствии LibreOffice `soffice.exe`.
Структурная проверка DOCX и успешно проверенный отдельный PDF не означают,
что вёрстка DOCX визуально проверена в Word или Google Docs. Перед внешним
распространением DOCX откройте его в целевом редакторе и проверьте страницы.
Нет авторизации для доступа извне, многопользовательского режима и облачного
размещения; сервис намеренно привязан к локальному компьютеру.
# Корпус статей и постов

Модуль `src/corpus_pipeline` добавляет к сервису обработку собственных выгрузок.
После запуска `Start-SemanticSpace.ps1` откройте
http://127.0.0.1:8766/corpus или ссылку «Корпус материалов» на главной странице.

## Последовательность обработки

1. **Импорт CSV.** Введите абсолютный путь к файлу на компьютере сервера.
   Автоматически определяются кодировка, разделитель и столбцы. Поддерживаются
   русские и английские заголовки, многострочные поля и отдельный OCR.
   Можно явно указать сопоставление столбцов. Числовые идентификаторы остаются
   строками: научная нотация в исходном CSV не восстанавливает утраченную точность.
2. **Проверка очистки.** Оригинал сохраняется неизменным. Пустые записи и точные
   дубли получают отдельные статусы; для смысловой обработки выбираются
   представители точных дублей. Поля источника и связи с оригиналами сохраняются.
   Похожие перепечатки ищутся по шинглам с ограничением числа сравнений;
   это кандидаты на проверку, они не удаляются автоматически. Такой поиск
   не гарантирует обнаружения переводов и всех сообщений об одном событии.
3. **Настройка исследования.** Задайте область, период, языки и объекты с
   вариантами имён. Можно скопировать утверждённый список существующего
   исследования. Копирование не изменяет исходное исследование и не переносит
   согласование шкал. Для Руанды подставляются согласованные языки и обязательный
   блок страны. Публичные позиции и чужие характеристики образа — разные режимы.
4. **Подготовка заданий.** Выберите этап и число новых заданий. Эта операция
   не вызывает API и показывает консервативный резерв стоимости очереди.
   Длинные документы делятся на перекрывающиеся окна с сохранением полного
   покрытия; оригинал целиком не повторяется в каждом запросе.
5. **Отдельный запуск API.** Задайте лимит заданий и бюджет этого запуска.
   По умолчанию пробный запуск ограничен пятью заданиями. При недостаточном
   резерве следующее задание остаётся в очереди. Бюджет относится к заданным
   ставкам; фактический счёт определяется провайдером.
6. **Результаты этапов.** `relevance` проверяет личности, содержание и язык;
   `extract` извлекает дословные фрагменты с авторством и политической ролью;
   `describe` предлагает определения и критерии самостоятельных признаков;
   `score` оценивает утверждённые признаки 0–5 с устойчивыми ID свидетельств.
   Ошибки API и неподтверждённые цитаты не становятся содержательным unknown.
7. **Согласование словаря.** Черновики признаков видны в интерфейсе и переносятся
   в редактор без автоматического утверждения. При большом корпусе они формируются
   по группам свидетельств: перед утверждением нужно объединить одинаковые
   определения между группами, проверить единый уровень описания и критерии
   баллов. Для каждого признака обязательны определение и якоря 0, 3 и 5.
   Редактирование словаря снимает его согласование, если оно явно не подтверждено
   в том же сохранении. Частота эпизодов не является силой свойства.
8. **Экспорт.** Сохраняются профиль, проверяемые фрагменты, черновики шкал,
   предварительные оценки, кандидаты дублей и происхождение. Это отдельная
   версия входа для последующего анализа; прежняя модель Руанды и её отчёты
   автоматически не пересчитываются. Перед общей факторной моделью нужны
   проверка событий, покрытие, согласованность разметки и агрегация по периодам.

## Модели и расходы

Маршруты настраиваются отдельно: исходные значения — `gpt-4.1-nano` для отбора
и `gpt-5.1` для извлечения, словаря и оценивания. Модели не заменяются автоматически.
Для другой модели нужно задать её входную, выходную и кэшированную входную
стоимость в USD за миллион токенов. Неизвестная цена блокирует подготовку,
а не считается нулевой. Начальные ставки проверены 17.10.2026:
[официальные тарифы](https://developers.openai.com/api/docs/pricing),
[GPT-5.1](https://developers.openai.com/api/docs/models/gpt-5.1),
[GPT-4.1 nano](https://developers.openai.com/api/docs/models/gpt-4.1-nano).

Ключ задаётся только в локальном `.env` как `OPENAI_API_KEY` или в окружении
процесса. Ввод ключа через интерфейс и сохранение в настройках корпуса не
предусмотрены. В этой версии вызовы синхронные, с очередью и без автоматических
повторов. Отправка через Batch API и автоматическая эскалация на другую модель
не реализованы. Сначала следует сравнить модели на размеченном пилоте по
каждому языку, особенно по киньяруанда, и проверить ошибочно исключённые тексты.

## Хранение и продолжение

SQLite и неизменные оригиналы находятся в `.corpus_runtime/`, исключённой
из Git. В API отправляются исследовательские поля документа и его фрагмент;
демографические поля выгрузки не включаются в запрос автоматически.
Тексты документов и содержащиеся в них команды всегда рассматриваются как
данные; обработчик не исполняет их и не переходит по ссылкам за пределы задания.

Готовые задания повторно не оплачиваются. Хэши связывают задачи с версией
источника, моделями и смысловыми настройками; изменение шкал не требует заново
оплачивать отбор документов. Старые оценки с другим снимком свидетельств
исключаются из текущего экспорта. Файлы экспорта записываются атомарно в каталог,
чей хэш охватывает всё содержимое снимка.

После остановки процесса оставшаяся очередь сохраняется. Задания с неясным
результатом запроса автоматически не повторяются: их оплата может быть неизвестна.
Отказ с известным usage учитывается как расход; отказ или повреждённый ответ
без usage сохраняет резерв и требует проверки. При аварийном завершении
процесса отметьте оставшиеся running командой `recover-interrupted`; она
переведёт их в uncertain без повторного запроса. Полностью автоматического
согласования таких запросов со счётом провайдера в этой версии нет.

## Командная строка

Используйте Python с зависимостями `requirements-service.txt` из окружения
сервиса. Примеры команд из корня проекта:

```powershell
python -m src.corpus_pipeline import 'C:\Data\export.csv' --title 'Мой корпус'
python -m src.corpus_pipeline list
python -m src.corpus_pipeline show <corpus-id>
python -m src.corpus_pipeline configure <corpus-id> config.json
python -m src.corpus_pipeline prepare <corpus-id> --stage relevance --limit 100
python -m src.corpus_pipeline run <corpus-id> --execute --max-jobs 5 --budget-usd 1
python -m src.corpus_pipeline export <corpus-id>
python -m src.corpus_pipeline recover-interrupted <corpus-id>
```

`<corpus-id>` нужно заменить идентификатором из импорта. Без `--execute` CLI
не запускает API. `retry-errors` повторно ставит в очередь только известные
неоплаченные ошибки и не затрагивает uncertain/review.
