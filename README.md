Исследовательский проект: восстановление компактного семантического пространства
по свойствам его объектов, интерпретация латентных осей, группировка объектов и
сравнение заполненности областей пространства. Механизм предполагается общим
для разных доменов; словарь признаков и смысл осей определяются отдельно для
каждого пространства. Политические партии — первый исследовательский пример.

Исходная матрица описывает партии; новый пилот — публичные образы политиков.
Оценки признаков даёт языковая модель по досье с источниками. Полученные
кластеры являются группами объектов в модельном пространстве.
Это разведочный этап изучения публичных образов/идей. Утверждения
о действительных электоратах и распространённости установок среди граждан
требуют дополнительных данных; для самого исследования объектов опрос граждан
не является обязательным предварительным условием.

## Установка и офлайн-аудит

Аудит выполнен в существующем окружении исходного проекта. Точные версии пакетов
и Python записаны в `reports/audit/methodology_audit.json`.
Диапазоны версий в исходном `requirements.txt` сами по себе не обеспечивают
воспроизводимость; для нового окружения используйте проверенный снимок зависимостей.

```powershell
python -m venv venv
.\venv\Scripts\python.exe -m pip install -r requirements-audit.txt
.\venv\Scripts\python.exe scripts/methodology_audit.py
.\venv\Scripts\python.exe scripts/score_numerics_audit.py
```

Аудит не обращается к API, не расходует бюджет моделей и не перезаписывает `data/`.
Параллельный анализ в нём относится к PCA: это диагностическая оценка размерности,
а не автоматический выбор числа общих факторов EFA. Устойчивость кластеров
проверяется при фиксированных факторных баллах, а не для всего процесса измерения.

Отдельный прототип устойчивого латентного пространства:

```powershell
.\venv\Scripts\python.exe scripts/latent_space_benchmark.py
.\venv\Scripts\python.exe -m unittest discover -s tests -v
```

Результаты FA/PCA пишутся в `reports/latent_benchmark/`, исходный CLI не изменён.
[Описание проверки и примеры карт](reports/latent_benchmark/README.md).

## Исходный пайплайн

Создайте локальный `.env` по образцу `.env.example` и настройте `config/config.yaml`.

```powershell
python -m src.cli run --stage all --dry-run
python -m src.cli run --stage all --apply
```

Второй вызов выполняет платные запросы и перезаписывает результаты.
Перед методологически новым запуском используйте отдельный каталог результатов
и сохраните конфигурацию, версии промптов и источники. Исходная спецификация
описывает задуманный алгоритм; выявленные расхождения с реализацией перечислены
в методологическом аудите.
